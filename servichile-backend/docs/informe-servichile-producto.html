1. Introducción

1.1 Propósito del documento

Este informe presenta ServiChile como producto funcional. Resume el problema que resuelve, lo que ya se puede usar, el mapa de pantallas y cómo levantarlo en local.

2. Problema, promesa y alcance del producto

2.1 Problema

En el mercado chileno, contratar un proveedor entre empresas sigue siendo un proceso lento, manual y lleno de puntos ciegos. Cuando una compañía necesita externalizar un servicio o sumar un nuevo socio comercial, la búsqueda suele resolverse a través de recomendaciones de conocidos, cadenas de correos o búsquedas en internet donde todos prometen resultados similares, pero casi nadie respalda lo que dice con hechos verificables.

El primer gran obstáculo es que la información pública de las empresas está dispersa y es difícil de auditar. Un sitio web bien diseñado o un perfil en redes sociales no están garantizando experiencia ni capacidad operativa y mucho menos cumplimiento legal.

En ese escenario, contratar a ciegas se vuelve la norma, exponiendo a las empresas a incumplimientos de contrato, retrasos críticos en su operación, pérdidas económicas y problemas legales que pudieron evitarse desde el primer contacto.

2.2 Promesa del producto construido

ServiChile ofrece un catálogo B2B con señales medibles:

  • 1Índice de Transparencia del proveedor: qué cumple y cómo.
  • 2Verificación de identidad de personas y contratistas con biometría, cédula y antecedentes.
  • 3Trabajos con QR para cerrar encargos con trazabilidad.
  • 4Pagos Webpay por informe de proveedor a $9.990 y por publicación de ficha a $8.990.

2.3 Producto como solución

ServiChile es una plataforma chilena que agrega una capa de confianza verificable antes de cerrar cualquier contratación entre empresas, transformando datos dispersos en evidencia objetiva y comparable.

El sistema articula tres perfiles: persona, contratista y proveedor. Este último publica su empresa en un catálogo abierto donde cada ficha muestra un Índice de Transparencia de cero a diez, calculado automáticamente cruzando datos de su sitio web, Google Places, ChileCompra y documentos formales, con opción de recálculo inmediato por parte del titular. Esta vitrina pública ordena y filtra el mercado desde el primer vistazo, mientras que el radar comercial profundo audita riesgos legales, contratos y ciberseguridad, y se desbloquea bajo pago antes de tomar la decisión final.

Para reemplazar las reseñas informales por respaldo real, la confianza se acredita con identidad y trazabilidad. Las personas validan su cuenta con RUT, cédula y biometría para emitir un Reporte de Confianza verificable por código QR. Cuando un comprador inicia un servicio con un proveedor documentado, el titular utiliza ese mismo QR para certificar si el trabajo se concretó o no, amarrando el historial comercial a transacciones reales.

Sobre esta base, ServiChile monetiza directamente en el momento de contratar a través de dos mecanismos:

  • 1Informes de riesgo a demanda: pago único de $9.990 vía Webpay Plus para recibir por correo el informe en PDF, el código QR de verificación y el comprobante.
  • 2Contactos calificados: el comprador indica si quiere cotizar, evaluar un proveedor fijo o una licitación, más el rango de monto y el plazo. Con eso se arma el mensaje y se abre WhatsApp o correo hacia el proveedor.

3. Estado real construido

ServiChile es un producto funcional en entorno local. El frontend es una PWA en HTML, CSS y JavaScript modular. El backend es FastAPI sobre PostgreSQL 16 y Redis 7, con capas verificadas por import-linter.

6.3 Pantallas de privacidad y cookies

Política de privacidad: vigente desde noviembre de 2026 y alineada a la Ley 21.719. Explica el tratamiento de datos de cuenta, ficha de empresa y documentos del índice. Permite borrar la cuenta desde el perfil. No se venden bases de clientes y no reemplaza asesoría legal.

Uso de cookies: solo para el funcionamiento de la app. Cubre sesión, consentimiento del aviso de entrada y preferencias de ficha, sin publicidad ni seguimiento. El usuario puede rechazar lo no necesario.

Términos y condiciones: cierran el bloque legal y se enlazan desde el pie de estas pantallas y de la app.

8. Manual de uso e instalación

Objetivo: que un tercero levante el producto en local y complete un recorrido mínimo sin adivinar. El stack está pensado para ejecutarse en Windows, Linux, Ubuntu y macOS.

8.1 Requisitos

  • 1Sistema operativo: Windows, Linux, Ubuntu o macOS
  • 2Python 3.12
  • 3Docker con Postgres 16 y Redis 7
  • 4Cliente psql
  • 5Puertos 5432, 6379, 8000 y 5500 libres
  • 6Opcional para cédula: Tesseract con idioma spa, instalado con el gestor de paquetes de cada sistema

8.2 Instalación del backend

Pasos en la terminal:

1

Entrar al backend

cd servichile-backend
2

Crear y activar el entorno virtual

python3.12 -m venv .venv
# macOS, Linux y Ubuntu:
source .venv/bin/activate
# Windows:
.venv\Scripts\activate
3

Instalar dependencias de desarrollo

pip install -r requirements-dev.txt
4

Preparar .env con JWT_SECRET, DATABASE_URL y REDIS_URL

cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
# Pegar el valor en JWT_SECRET, mínimo 32 caracteres
5

Levantar Postgres y Redis

docker run -d --name servichile-db -p 5432:5432 \
  -e POSTGRES_USER=servichile -e POSTGRES_PASSWORD=servichile -e POSTGRES_DB=servichile \
  postgres:16
docker run -d --name servichile-redis -p 6379:6379 redis:7-alpine
6

Crear esquema y datos demo

psql "postgresql servichile:servichile@localhost:5432 servichile" -v ON_ERROR_STOP=1 -f db init_script.sql
python -m scripts.cargar_db_demo
7

Arrancar la API

uvicorn app.principal:app --reload --port 8000

Frontend en otro terminal

8

Servir la PWA en el puerto 5500

cd servichile-frontend
python3 serve.py 5500

URLs: API localhost:8000 docs, Front localhost:5500 index.html, Salud localhost:8000 salud.

Comprobación mínima: GET localhost:8000 salud debe responder 200 con dependencias.redis y dependencias.postgres en ok, más smtp según configuración. Una ruta inventada en el API o en el front debe mostrar el 404 personalizado.

9. Conclusión

A lo largo de su desarrollo, ServiChile evolucionó desde una propuesta inicial centrada en asistencia generativa hacia una plataforma B2B especializada en verificación, transparencia y respaldo comercial entre empresas. Este giro permitió dejar atrás la generación probabilística de texto para consolidar un producto basado en evidencia medible, trazabilidad operativa y validación objetiva antes de cerrar una contratación.

El sistema entregado cumple con el flujo completo del negocio: permite el registro de cuentas, la exploración de proveedores mediante indicadores públicos de transparencia, la acreditación de identidad real y el seguimiento de servicios ejecutados mediante códigos QR. Asimismo, integra de forma nativa la monetización del modelo a través de Webpay para la compra de informes de riesgo y la gestión de publicaciones, garantizando control en el flujo de transacciones.

En el plano técnico, la arquitectura final compuesta por una aplicación web progresiva, un monolito estructurado por capas, PostgreSQL y Redis refleja de manera fiel tanto el código implementado como los diagramas detallados en este documento. La bitácora del proyecto da cuenta de esta maduración, documentando el paso del asistente conversacional al índice de transparencia, la resolución de incidencias asociadas a la persistencia de sesión en Webpay y el endurecimiento de la seguridad en los módulos de pago y caché.

Con ello, el sistema queda completamente documentado y operativo para su despliegue y uso en entorno local siguiendo los pasos del manual de la sección 8, mientras que el video promocional del producto será entregado por separado como complemento de esta presentación.

B.1 Herramientas de IA usadas en el desarrollo

B.3 Medidas aplicadas

  • 4Rate limits de login por Redis por cuenta e IP.
  • 5Minimización: foto de cédula y PDFs de perfil no se retienen.
  • 6Caché pública solo del teaser. Cuerpo pagado con Cache-Control: private, no-store.
  • 7Banner de cookies y cumplimiento local en el frontend con compliance.js.
